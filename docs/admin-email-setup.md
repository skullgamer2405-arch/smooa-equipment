# เชื่อมอีเมลแจ้งเตือนผู้ดูแล SMO OA

## ระบบทำอะไรให้

- เมื่อส่งคำขอยืมใหม่ผ่านเว็บหรือ LINE ระบบส่งรายละเอียดให้ผู้ดูแลหนึ่งอีเมล: อุปกรณ์ ผู้ยืม กิจกรรม วันยืม–คืน และรหัสคำขอ
- หากตั้ง URL เว็บจริงไว้ อีเมลจะมีลิงก์เปิดหน้าแอดมิน ผู้ดูแลต้องเข้าสู่ระบบตามปกติ การคลิกลิงก์ไม่ได้อนุมัติคำขอ
- เมื่อผู้ดูแลอนุมัติหรือปฏิเสธ ระบบส่งผลไปยังอีเมลผู้ยืมที่บันทึกในคำขอ
- การส่งคำขอเดิมซ้ำจะไม่ส่งอีเมลซ้ำ หากผลส่งไม่ชัดเจน ระบบแสดง «ต้องตรวจผลการส่ง» เพื่อให้ตรวจกล่องจดหมาย/ผู้ให้บริการก่อนส่งใหม่
- งานนี้เป็นการแจ้งคำขอและผลพิจารณาทางอีเมล การเตือนคืนทาง LINE เป็นระบบแยก

ยังไม่ได้เชื่อม Gmail หรือส่งอีเมลจริงจากการพัฒนา การทดสอบใช้ข้อมูลจำลองเท่านั้น หน้า Preview ของ Vercel ปิด API จริงเสมอ แม้ใส่ค่าครบแล้วก็ไม่ส่งเมล ต้องตรวจในสภาพแวดล้อมทดสอบแยกที่เปิด API จริงก่อนเปิดใช้ production

การเชื่อม Firebase และตั้งค่าครบก่อนเปิดจริงดู [คู่มือ Production](production-setup.md)

## วิธีแนะนำ: Gmail ผ่าน SMTP

SMTP คือช่องทางให้เซิร์ฟเวอร์ของเว็บส่งอีเมลผ่าน Gmail ไม่ต้องสร้าง Google Apps Script และไม่ต้องใช้ Google AI Studio API key

### 1. เลือกอีเมลสองหน้าที่

- **ผู้ส่ง**: บัญชี Gmail สำหรับส่งแจ้งเตือน เช่น บัญชีของทีม ควรเป็นบัญชีที่เจ้าของอนุญาตให้ใช้
- **ผู้รับ**: อีเมลผู้ดูแลที่จะได้รับคำขอยืมใหม่ ใช้ Gmail หรือผู้ให้บริการอื่นได้ ผู้ส่งกับผู้รับเป็นบัญชีเดียวกันได้

อีเมลผู้รับนี้ไม่ใช่การเพิ่มสิทธิ์แอดมิน ผู้ที่เข้าเว็บยังต้องมีบัญชี Firebase ที่ยืนยันอีเมลแล้วและมีสิทธิ์ `admin=true` ตาม [คู่มือเปิดใช้งานระบบ](agents/ux-privacy-rollout.md)

### 2. สร้าง App Password ของบัญชีผู้ส่ง

1. เข้าบัญชี Google ของ **อีเมลผู้ส่ง** ที่ [myaccount.google.com/security](https://myaccount.google.com/security)
2. เปิด **การยืนยันแบบ 2 ขั้นตอน (2-Step Verification)**
3. เปิด [App passwords](https://myaccount.google.com/apppasswords) ตั้งชื่อเช่น `SMO OA email` แล้วสร้างรหัสผ่านสำหรับแอป
4. Google จะแสดงรหัส 16 ตัว ใช้รหัสนี้เป็น `SMTP_PASS` ในขั้นตอนถัดไป ไม่ใช่รหัสผ่านล็อกอิน Google ตามปกติ

หากไม่เห็นเมนู App passwords บัญชีอาจถูกจำกัดโดยองค์กร/Advanced Protection หรือวิธีการยืนยันตัวตน ให้ผู้ดูแล Google Workspace ตรวจนโยบาย หรือใช้ผู้ให้บริการ SMTP ที่องค์กรอนุมัติ อย่าปิดระบบความปลอดภัยเพื่อให้ส่งเมลได้

อย่าส่ง App Password ในแชต ไม่ใส่ใน GitHub หรือไฟล์ที่ commit หากเผลอเผยแพร่ให้เพิกถอนแล้วสร้างใหม่

### 3. ใส่ค่าใน Vercel

เปิด **Vercel → โปรเจกต์ smooa-equipment → Settings → Environment Variables** แล้วเพิ่มค่าต่อไปนี้ให้ฝั่งเซิร์ฟเวอร์ **service `api`** (หากหน้าจอไม่มีช่องเลือก service ให้ใช้ค่าระดับโปรเจกต์ที่ API อ่านได้) ห้ามตั้งชื่อขึ้นต้นด้วย `VITE_` เพราะจะเผยแพร่ไปกับหน้าเว็บ

| ชื่อตัวแปร | ค่าที่ใส่ |
| --- | --- |
| `ADMIN_NOTIFICATION_EMAIL` | อีเมลผู้ดูแลที่รับแจ้งเตือน **หนึ่งที่อยู่** ไม่ต้องมีเครื่องหมาย `< >` |
| `SMTP_HOST` | `smtp.gmail.com` |
| `SMTP_PORT` | `587` |
| `SMTP_SECURE` | `false` — พอร์ต 587 ใช้ STARTTLS เพื่อเข้ารหัส |
| `SMTP_USER` | อีเมล Gmail ผู้ส่งแบบเต็ม |
| `SMTP_PASS` | App Password 16 ตัวจากขั้นตอน 2 คัดลอกโดยไม่เว้นวรรค |
| `PUBLIC_APP_URL` | URL หลักของเว็บจริง เช่น `https://ชื่อเว็บของคุณ.vercel.app` ไม่ใช่ URL หน้า dashboard ของ Vercel |

`SMTP_FROM` เว้นว่างได้ ระบบใช้ `SMTP_USER` เป็นผู้ส่ง หากจะระบุเองต้องเป็นที่อยู่ที่บริการส่งอนุญาต

เลือก environment ให้ตรงกับการใช้งานจริงแล้วบันทึก **ค่าใหม่จะใช้เมื่อ Redeploy เท่านั้น** บัญชีส่งมีโควตาของ Gmail/Workspace หากโควตาหมดหรือถูกระงับ ระบบส่งไม่ได้ ไม่ถือว่ามีการส่งแบบไม่จำกัด

### 4. ตรวจ backend แล้ว Redeploy

ก่อนเปิดใช้จริง ผู้ดูแล deployment ต้องตรวจว่า:

- `/api/*` ไปถึง service `api` ตาม `vercel.json`
- API มี `FIREBASE_SERVICE_ACCOUNT_JSON` ที่ถูกต้อง และบัญชีแอดมินเข้าใช้งานได้ ไม่เปิดเผย JSON นี้ในแชต
- environment ที่เปิดใช้งานจริงไม่มี `SMO_DEMO_MODE=true` หรือ `VITE_DEMO_MODE=true`; สำหรับ Vercel Preview ระบบบังคับโหมดจำลองอยู่แล้ว ไม่ต้องแก้ตัวป้องกันนี้เพื่อทดลองส่ง
- ตรวจบน test project/สภาพแวดล้อมแยกที่ใช้ Firebase และผู้รับทดสอบก่อน จากนั้นค่อย deploy production ตามขั้นตอนของทีม

ใน Vercel เปิด **Deployments → เลือก deployment ของ environment ที่ตั้งค่า → Redeploy** การใส่อีเมลอย่างเดียวไม่ได้ทำให้ backend ที่ยังไม่ตั้ง Firebase พร้อมใช้งาน

### 5. ทดสอบจากหน้าแอดมิน

1. เปิดเว็บและเข้าสู่ระบบผู้ดูแล → **การตั้งค่า** → **อีเมลแจ้งเตือน**
2. ตรวจผู้รับและช่องทางส่ง ระบบควรแสดง `SMTP` และ «ตั้งค่าครบแล้ว — ส่งทดสอบเพื่อยืนยันการเชื่อมต่อ» ข้อความนี้หมายถึงมีค่าครบ ยังไม่ยืนยันรหัสผ่านหรือสิทธิ์ส่ง
3. หากใช้ SMTP ให้ลบช่อง **URL ของ Google Apps Script** ให้เป็นช่องว่าง แล้วกด **บันทึกการตั้งค่า** เพราะ URL ที่มีอยู่จะทำให้ระบบเลือก Apps Script แทน SMTP
4. กด **ส่งอีเมลทดสอบ** หนึ่งครั้ง ระบบส่งไปที่ `ADMIN_NOTIFICATION_EMAIL` เท่านั้น
5. ตรวจกล่องรับและโฟลเดอร์สแปม ข้อความ «บริการอีเมลตอบรับแล้ว» ยังไม่ใช่หลักฐานว่าเข้ากล่องรับแล้ว
6. ในสภาพแวดล้อมทดสอบ ส่งคำขอยืมด้วยข้อมูลจำลอง ตรวจว่าเมลมาถึง มีวันยืมคืนถูกต้อง และลิงก์หน้าแอดมินเปิดได้ ตรวจส่งคำขอเดิมซ้ำว่าไม่เกิดเมลซ้ำ

คำขอที่เกิดก่อนตั้งค่าอีเมลไม่ได้ถูกส่งย้อนหลังอัตโนมัติ อย่ากดส่งทดสอบซ้ำเร็ว ๆ เพราะแต่ละครั้งเป็นอีเมลคนละฉบับ

## ถ้าเมลยังไม่มา

| สิ่งที่พบ | วิธีตรวจ |
| --- | --- |
| «โหมดตัวอย่าง — ไม่ส่งอีเมลจริง» | กำลังใช้ Preview/โหมดจำลอง ใช้ตรวจ UI เท่านั้น |
| «ยังตั้งค่าอีเมลไม่ครบ» | ทำตามรายการที่หน้าจอระบุ ตรวจชื่อตัวแปรและ environment แล้ว Redeploy |
| ส่งผ่าน Apps Script ทั้งที่ตั้ง Gmail แล้ว | ลบ URL Apps Script และบันทึกเพื่อเลือก SMTP |
| «ต้องตรวจผลการส่ง» | ตรวจกล่องรับ/สแปม App Password โควตา และข้อมูลจากผู้ให้บริการก่อนส่งใหม่ การส่งอาจสำเร็จแต่คำตอบกลับหายได้ |
| หน้าตั้งค่าโหลดไม่ได้/เข้าแอดมินไม่ได้ | ตรวจ Firebase Admin, custom claim และ routing ของ API ก่อน ไม่ใช่ปัญหา Gmail อย่างเดียว |
| ลิงก์เข้าเว็บไม่มีในเมล | ตั้ง `PUBLIC_APP_URL` เป็น HTTPS ของเว็บจริง ไม่ใส่ username/password ใน URL แล้ว Redeploy |
| บริการตอบรับแต่ไม่อยู่ใน Inbox | ตรวจ Spam/All Mail และการกรองเมลของผู้รับ การตอบรับไม่ได้รับประกันการส่งถึงกล่องรับ |

## ทางเลือก: ใช้ Google Apps Script ที่มีอยู่

ใช้วิธีนี้แทน SMTP หากต้องการใช้ MailApp และบัญชีอนุญาต:

1. สร้างโปรเจกต์ที่ [script.google.com](https://script.google.com) ด้วยบัญชีผู้ส่ง แล้วคัดลอกไฟล์ [google_apps_script_email.js](../google_apps_script_email.js) ทั้งไฟล์ลงในตัวแก้ไข
2. สร้าง secret แบบสุ่มอย่างน้อย 32 ตัวด้วยตัวจัดการรหัสผ่าน ตั้งใน **Project Settings → Script Properties** ชื่อ `SMO_WEBHOOK_SECRET`
3. ตั้ง `APPS_SCRIPT_SHARED_SECRET` ใน Vercel เป็น **ค่าเดียวกัน** และตั้ง `ADMIN_NOTIFICATION_EMAIL` กับ `PUBLIC_APP_URL` ตามด้านบน ไม่ต้องตั้ง SMTP หากใช้วิธีนี้อย่างเดียว
4. ใน Apps Script เลือก **Deploy → New deployment → Web app**, Execute as **Me**, Who has access **Anyone** แล้วอนุญาตสิทธิ์ส่งอีเมลด้วยบัญชีผู้ส่ง โค้ดตรวจลายเซ็นจาก secret ทุกครั้ง แม้ endpoint เปิดรับอินเทอร์เน็ต หากองค์กรไม่อนุญาต Anyone ให้ใช้ SMTP ที่องค์กรอนุมัติแทน
5. คัดลอก URL ที่ลงท้าย `/exec` ตั้งใน Vercel ชื่อ `APPS_SCRIPT_WEBHOOK_URL` คู่กับ secret เพื่อให้ release check ตรวจช่องทางส่งได้ และใส่หน้าแอดมินแล้วบันทึก ค่าที่บันทึกในแอดมินจะทับค่าเริ่มต้นนี้ รวมถึงช่องว่างเพื่อปิด หากแก้โค้ดภายหลังต้อง deploy เวอร์ชันใหม่ของ Web app ด้วย
6. Redeploy API หลังเปลี่ยน environment แล้วกดส่งทดสอบและตรวจเมลตามขั้นตอน 5

Apps Script มีโควตาการส่งของตนเองเช่นกัน อย่าส่งรหัสลับหรือข้อมูลผู้ยืมจริงให้ผู้อื่นเพื่อช่วยตรวจปัญหา
