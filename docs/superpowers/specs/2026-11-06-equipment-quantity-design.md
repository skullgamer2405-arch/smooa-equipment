# จำนวนอุปกรณ์และจำนวนที่ขอยืม

เจ้าของต้องการปุ่ม + / − ในฟอร์มเพิ่มอุปกรณ์และฟอร์มขอยืม แสดงจำนวนคงเหลือบนหน้าผู้ใช้ และซ่อนรายการที่ยืมหมดแล้ว

## พฤติกรรม

- `equipment.quantity` คือจำนวนทั้งหมด เป็นจำนวนเต็ม 1–10,000; รายการเดิมที่ไม่มีค่าเท่ากับ 1 ชิ้น
- `equipment.borrowedQuantity` คือจำนวนที่อนุมัติแล้วและยังไม่รับคืน เซิร์ฟเวอร์คำนวณจากคำขอที่สถานะ approved ภายใน transaction เดียวกับการเปลี่ยนสถานะ
- `bookings.quantity` คือจำนวนที่ขอยืม จำนวนเต็ม 1–10,000; คำขอเดิมเท่ากับ 1
- คำขอ pending ยังไม่กันของ ตรวจยอดตอนส่งคำขอและอีกครั้งตอนอนุมัติ ป้องกันอนุมัติพร้อมกันจนเกินจำนวน ไม่จองตามช่วงวันล่วงหน้า เพราะระบบเดิมถือว่าอนุมัติแล้วของไม่ว่างจนรับคืน
- คงเหลือ = จำนวนทั้งหมด − จำนวนที่ยังไม่คืน เมื่อสถานะ available และเหลือมากกว่า 0 จึงขอยืมได้ รายการหมดซ่อนจากหน้าแรกและรายการอุปกรณ์ผู้ใช้ ผู้ดูแลและประวัติยังเห็น
- เจ้าของยืนยันให้ทยอยคืนได้: bookings.returnedQuantity เก็บจำนวนที่รับคืนสะสม เริ่มที่ 0; ค้างคืน = quantity − returnedQuantity รับคืนแต่ละครั้งใช้ quantity และ UUID requestId เพื่อกันการส่งซ้ำ transaction จะคืนเฉพาะจำนวนที่ได้รับจริง คง approved และการเตือนเมื่อยังค้าง เปลี่ยนเป็น returned และหยุดเตือนเมื่อรับครบ ไม่เปลี่ยน maintenance เป็น available โดยอัตโนมัติ
- ผู้ยืมและผู้ดูแลเห็นจำนวนที่ยืม คืนแล้ว และค้างคืน; ข้อความ LINE ระบุจำนวนค้างคืนล่าสุด
- การแก้จำนวนทั้งหมดต้องไม่น้อยกว่าที่อนุมัติค้างอยู่ ห้ามลบรายการที่ยังมีคำขอ approved
- แสดงจำนวนในคำขอผู้ดูแล ใบรับคำขอ รายการของฉัน อีเมลและ LINE โดยคงการหยุดเตือนหลังรับคืน
- เปลี่ยน equipment CRUD ไปผ่าน API ผู้ดูแลเพื่อตรวจยอดพร้อม transaction; Firestore rules ปิด client writes ของ equipment เช่นเดียวกับ bookings
- ปุ่มสัมผัสอย่างน้อย 44px มีชื่อสำหรับโปรแกรมอ่านหน้าจอ ช่องตัวเลขใช้คีย์บอร์ดได้ ปุ่มลบปิดที่ขั้นต่ำ ปุ่มเพิ่มปิดที่จำนวนสูงสุด ส่งฟอร์มไม่ได้เมื่อเกินคงเหลือ

## วิธีที่เลือกและขอบเขต

ใช้จำนวนรวมต่ออุปกรณ์หนึ่งรายการตามคำขอของเจ้าของและโครงสร้างรายการเดิม การแยกเอกสารหนึ่งชิ้นต่อหนึ่งรหัสจะต้องเปลี่ยนงานสร้างอุปกรณ์และ QR เกินขอบเขต ส่วนเก็บยอดเฉพาะหน้าเว็บป้องกันการอนุมัติพร้อมกันไม่ได้ จึงใช้ Firestore transaction พร้อมยอดสรุปที่อ่านจาก public equipment ได้

ไม่เพิ่มแพ็กเกจ ไม่ย้ายฐานข้อมูล ไม่แก้ข้อมูลผู้ยืมจริง และรักษางานค้างใน checkout เดิม ใช้ worktree feat/equipment-quantity จาก main d5c939a การทดสอบใช้ fixtures และ emulator ใน container ปิดเครือข่าย รายการเก่าปรับโครงสร้างเมื่อมีการแก้ไข/อนุมัติ/รับคืน ไม่เขียน migration ทับ production

จำกัดที่ 100 คำขอ approved ต่ออุปกรณ์ อนุมัติคำขอที่ 101 ไม่ได้ แต่ยังรับคืนและแก้ไขที่ 100 ได้ ปุ่มรับคืนในรายการอุปกรณ์พาไปเลือกคำขอของผู้ยืม ไม่มีการรับคืนเหมาทุกคำขอ เพื่อไม่รับคืนรายการที่เพิ่งอนุมัติโดยผู้ดูแลอีกคน
